# Represent plural strings as category maps

Radia localization YAML will represent a Plural String directly as a map of CLDR category names such as `one` and `other`, without an exact-number selector or explicit `plural` marker. This keeps the common authoring form compact and readable; the runtime call explicitly identifies the one numeric String Argument that drives version-one selection, while schema validation distinguishes category maps from ordinary strings and requires `other`. Radia does not infer the driver merely from the numeric arguments, and multiple or nested plural selections are deferred. Any of the six CLDR category names is allowed for every locale, an omitted category selects `other`, and a valid category that the locale never selects remains harmlessly unused; unknown category names are rejected. Across locales, the same String Key may be a scalar in one locale and a Plural String map in another; during plural selection, the scalar is the universal form for every count. If any locale in the fully merged catalog uses a plural map for a key, every runtime request for that key must supply the plural-selection argument so behavior cannot fail only after switching locales. That argument is available to every translation even if the Default Locale does not display it; no other new argument may be introduced by a translation.
