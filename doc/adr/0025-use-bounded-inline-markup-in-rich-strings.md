# Use bounded inline markup in Rich Strings

Rich Strings in `localization.yaml` will use well-formed Radia Inline Content fragments supporting exactly `b`, `i`, `s`, `br`, and `kbd` initially; tag names are lowercase and case-sensitive, attributes are rejected except where a tag contract explicitly permits them, and String Arguments are inserted as text after markup parsing. Parsing is token-aware rather than XML-like: only valid String Placeholders and recognized Radia tags are special, while ordinary `<`, `>`, `&`, and non-placeholder braces remain literal without character entities. A backslash suppresses recognition when a valid placeholder or tag must be displayed literally, and `\\` represents a literal backslash. Radia deliberately does not interpret localized strings as HTML or Markdown, keeping translator-controlled content aligned with Text Host semantics and excluding browser markup, styling, scripts, images, events, and links whose navigation contract has not yet been designed.

YAML scalar processing owns whitespace: Radia preserves the decoded scalar exactly, converts each preserved newline into an Inline Content line break, and performs no later trimming or whitespace collapsing. Authors use folded block scalars such as `>-` for source-wrapped prose and literal block scalars such as `|-` for intentional rendered line breaks.

Translations may freely change or reposition `b`, `i`, `s`, and `br` structure, but each translation must preserve the Default Locale's exact multiset of `kbd` Binding IDs for that String Key. Missing, changed, or additional bindings are validation errors.
