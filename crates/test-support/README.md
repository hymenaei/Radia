This crate contains literal fixtures and small helpers shared by tests. It has no dependency on Radia's production crates. Consuming packages use it only as a dev-dependency. Fixture bytes must not be generated by the encoder or decoder under test.

`fixtures/lludp/` holds hand-built protocol vectors. `fixtures/textures/` holds JPEG 2000 samples and independent pixel expectations used by Assets, Render, Scene, and Viewer tests. Run `python fixtures/textures/generate_textures.py` from this crate to regenerate them.

`allocation` supplies a system allocator and synchronous measurements for the calling thread. Each consuming test binary installs the allocator itself. Use it to verify decoded-memory admission and release; it does not measure process RSS or work on other threads. Network's process-wide probes remain local to Network because their measurement scope differs.

Hex fixtures contain whitespace-separated tokens of exactly two ASCII hexadecimal digits. Signs and non-ASCII characters are rejected, with a one-based token position in the error.

Allocation measurements include the returned value. Live bytes can be negative when the operation frees existing storage. Peak bytes conservatively count old and replacement storage together during reallocation. Nested measurements panic without clearing the outer measurement, and unwinding resets measurement state. Allocator calls forward pointers and layouts unchanged to System; thread-local accounting does not allocate. Accounting stops when thread-local storage is unavailable during thread teardown.

For allocator checks, run `cargo +nightly miri test --target x86_64-unknown-linux-gnu -p test-support --test allocation`. The current Windows Miri target reports a standard-library allocator teardown error even with an empty test and System as the only allocator.
