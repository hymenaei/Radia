Radia separates simulator observations, accepted world state, derived scene data, and GPU resources. This document describes the current ownership and data flow. Product direction lives in [vision.md](vision.md); working rules live in [AGENTS.md](../AGENTS.md).

## Data flow

Simulator traffic enters through LLUDP circuits and HTTP capabilities. `network` manages delivery and connection lifecycles; `protocol` supplies wire representations and codecs. The viewer's session intake translates messages into domain observations, preserving source identity, ordering evidence, partial updates, and coverage loss. `world` validates and applies those observations. Local requests become authoritative simulator state only when confirmed by observations.

Login returns the personal inventory and Library roots and folder skeletons. `protocol` parses those bounded wire values; the viewer session translates them into normalized categories and owns the single mutable inventory model. The model exposes immutable snapshots and revisions, while the session publishes snapshots through a watch channel. Favorites lookup uses the personal folder type. Inventory fetches and edits enter through the same model mutation API.

UDP inventory messages and EventQueue inventory events enter that same session intake in delivery order and translate into atomic inventory deltas. The session applies each delta before handling the next event. A known folder version rejects an older delta or fetch result. An unknown or mismatched delta version leaves the folder incomplete and reports that it needs a refetch. The session publishes the resulting snapshot before forwarding those requests to the fetch coordinator, which gives them foreground priority. The worker reads folder completeness from the latest session snapshot, so a parent fetch that makes a previously complete child incomplete queues that child for a fetch. UDP and EventQueue updates without version evidence use their delivered order.
The session fetch coordinator discovers AIS v3 first and requests recursive children with a bounded depth. If AIS is not granted, it posts `FetchInventoryDescendents2` or `FetchLibDescendents2` in batches of at most ten folders. `network` transports bounded capability responses, `protocol` decodes AIS and legacy LLSD into validated wire types, and the viewer maps those types into one folder application at a time. The session applies each result through `Inventory::apply_folder_fetch` and discards older versions when the local folder is complete. Foreground folder requests preempt background work through the session fetch handle. The background walk starts with every known skeleton folder and follows newly fetched categories in both personal inventory and Library. It runs at most two requests at once, half of `network`'s four-request capability budget, leaving capacity for other capability traffic. Bounded queues and response limits contain memory use, and session cancellation stops the worker. Snapshot and loading-status watches expose progress to viewer consumers.

The session inventory handle also exposes a bounded edit queue. One worker processes edits in FIFO order, so edits to the same node cannot overtake each other. It creates folders with AIS v3 or the `CreateInventoryCategory` capability when AIS is absent, renames categories and items through AIS, and empties Trash through AIS. Moves and deletion to Trash use typed `MoveInventoryItem` and `MoveInventoryFolder` messages because AIS move is not implemented. The per-operation policy prevents editing roots, protected folders, or Library, while allowing their contents and their use as destinations or parents unless an operation-specific system-folder rule applies. AIS response metadata is decoded into typed protocol values, converted into `InventoryDelta`, and applied by the session owner before the operation reports success. UDP moves wait for the corresponding live update; a timeout marks the source and destination versions unknown so the fetch coordinator reloads them. AIS timeouts and transport failures with an uncertain outcome, as well as 410 responses, mark affected folders incomplete and queue their refresh before returning. Edits do not change the model or cache before confirmation, and confirmed changes use the same owner publication and cache path as other inventory updates.

After login, the session reads the shared `inventory.sqlite` cache and validates it against the login skeleton off-thread. It turns the result into parent-first folder units, then applies at most 128 units or 512 child rows per session-loop turn to the live inventory. Cached children appear in chunks. A folder stays incomplete until its final cached batch commits, and a fetch that completes or changes that folder first wins. Restore never retries a full model copy and never writes its own changes back to the cache. The fetcher can run between restore batches and reads completeness from the current snapshot. A cache miss or damaged database leaves folder fetching responsible for the missing data.

Render's scene reconciliation reads bounded World pages and change journals through the viewer's `WorldReader` bridge. It combines accepted object, terrain, and environment state with available assets, then publishes batches for the viewport's `SceneView`. GPU drawing borrows that view; it does not read network messages or mutate World.

The session intake converts LLUDP and EventQueue `ParcelProperties` into World observations, while LLUDP `ParcelOverlay` and region flag messages retain packet order. Parcel sequence IDs advance the current parcel across transports, so stale, selected, and collision replies cannot replace it. Only the primary simulator updates the agent's current parcel; overlays and region flags belong to every active region. World keeps parcel properties and the completed overlay beside the environment parcel selection. Overlay parts stay private until a complete grid can be published, so readers keep seeing the previous grid while a replacement is incomplete. A bounded `WorldReader` snapshot exposes the current parcel, overlay, and effective restrictions. Region retirement drops that region's parcel state.

Transport coverage loss and scene recovery are separate concerns. Session intake tracks where simulator observations may be incomplete and requests recovery where supported. Scene reconciliation can rebuild its derived state after history loss, rejected reads, or capacity pressure, but cannot recover observations that World never received. Neither successful rendering nor a populated scene proves complete simulator state.

## State and execution

The session intake task is the single owner of mutable World state. It services admitted read requests alongside incoming events; consumers receive bounded replies and revision notifications rather than locking World. Session and region identities, ordering clocks, and tombstones protect updates across deletion, local-ID reuse, and handoff.

`main` creates the Tokio service runtime and starts GPUI. Networking owns a separate runtime and network thread. The scene viewport owns its window/event-loop thread, `SceneView`, and renderer. Asset fetching and scene reconciliation run on service tasks; decoding, mesh generation, and texture preparation use blocking workers. Bounded queues, admission limits, cancellation, and generation checks keep slow or stale work from crossing lifecycle boundaries.

## Code map

Each entry identifies a crate's responsibility, its important boundaries, and constraints that callers must preserve. Module listings, numeric limits, and command references belong in source or [tooling.md](tooling.md).

### `apps/viewer`

Composes startup, GUI screens and primitives, persistence, and subsystem coordinators. Session intake is the sole owner of World and inventory, translating protocol messages into domain observations and deltas in source order and applying inventory fetches and edits. Parcel properties update World only for the primary simulator; overlays and region flags update the corresponding active region. The inventory worker composes capability discovery and bounded network requests with protocol's AIS and legacy LLSD decoders; it owns retries and foreground priority, then returns bounded folder results to the session owner instead of mutating the model. The asset coordinator runs network fetches on service workers and reserved cache reads, decodes, and writes on blocking workers. Successful network decodes enqueue bounded cache writes; session shutdown drains work already in flight. The viewer opens one cache at the local default location and shares raw cached payloads across sessions, while each session keeps its own Store and route state. The scene feed schedules reconciliation and delivers sequenced batches to the viewport.

The viewport owns held keyboard state and derives movement flags once per frame. It publishes coalesced movement and camera snapshots over watch channels to the session coordinator; focus loss publishes released controls immediately without waiting for a redraw. The coordinator sends control changes immediately, follows them with an 8 ms update, keeps the camera alive every second, and suppresses smaller camera and rotation changes. It clears outbound deadlines when no primary destination exists, then resumes updates when a primary simulator connects. Always-run changes use the reliable SetAlwaysRun message. Input never mutates World. The session publishes authoritative self-agent motion samples, and the viewport dead-reckons from those samples while keeping body yaw client-owned. The renderer draws the self avatar at that local pose. Follow mode is the default and uses the official rear-view offsets; the camera smooths its offset relative to the avatar focus. Wheel zoom, orbit, and pan stay attached to the avatar. Focusing a picked object enters a free camera without a jump; Esc or an uncaptured movement key returns to follow.

### `crates/assets`

`assets` decodes textures, materials, environments, and mesh LOD blocks. It owns their values and the bounded CPU mesh representation. Its per-session `Store` coordinates demand, route eligibility, priority, retries, refinement, cancellation, and work reservations. The viewer owns network fetching and decode scheduling, which keeps asset policy independent of transport.

Mesh headers and individual render LODs use separate demand entries. The validated header supplies ranges, so callers request only the LODs they need. Mesh blocks are limited to 32 MiB. Each LOD accepts at most eight faces, 65,535 vertices, and 196,605 triangle-list indices per face. LLSD expansion is bounded from packed stream counts. Mesh decoding reserves for compressed input and the bounded parse peak, then resizes to count-derived geometry before allocating output buffers. Physics is ignored and the skin block is never fetched. Mesh values are exposed to callers but are not yet part of scene selection or drawing.

The persistent cache covers textures, PBR materials, legacy materials, environments, and complete raw mesh assets. It does not write independently fetched mesh ranges. Locally generated prim meshes remain in Render's memory cache. `next_job` yields disk reads, network fetches, or decode inputs for retained texture data. Disk read and network response completions enter the same decode admission path; cache misses, corrupt data, and unavailable storage continue to fetch without consuming a failed attempt. Only successfully decoded, normalized network payloads enter the bounded asynchronous writer, and those payloads persist across sessions. Texture refinement reuses its retained source. Storage checks each kind's payload bound before opening or allocating for a cache read. The asset cache maps each resource to a namespace index and UUID. Its root declares directories and extensions, exposes usage counters, and admits writes only while in-flight and budget reservations stay within their bounds. It supplies storage with an eviction policy that ranks reconstruction value per stored byte using logical recency, persisted use frequency, fetch size, and an in-memory per-kind decode-time estimate. The `Store` holds a storage protection lease inside each shared demand lease, so a demand protects its key until the final consumer releases it. Persistent layout, hashing, quotas, recovery, process locking, and eviction belong to `storage`.

### `crates/llsd`

Owns LLSD values, Serde integration, and XML, binary, and notation codecs. Decode limits bound document size, nesting, value counts, and scalar or container sizes; callers can tighten them for their own admission budgets. The binary codec can decode one value from a prefix and report its consumed byte count. Whole-document decoding still rejects trailing bytes. Simulator messages and domain semantics belong to higher layers.

### `crates/inventory`

Owns normalized personal inventory and Library categories, items, parent and child indexes, link resolution, folder completeness, validated mutation planning, immutable snapshots, and the SQLite cache schema and queries. Snapshot queries include filtering items by asset type. One `inventory.sqlite` file under the default cache directory serves all grids and agents. `scopes` maps the unique `(grid_id, owner_id)` pair to a compact scope ID and cache generation; the login session maps the agent ID to the personal scope and `inventory-lib-owner` to the Library scope. Kind is derived from the active login and is not persisted. Categories and items use `(scope_id, id)` primary keys. Whole-scope reads use the primary-key prefix, and search uses the in-memory inventory indexes. Link targets stay in the item's asset ID and asset type, so link resolution needs no extra table or index.

The cache restores complete and incomplete folders. A folder remains complete only when its committed child set belongs to the current scope generation, its known server version matches the login skeleton, and its cached children agree with the skeleton. Other cached children stay visible while the folder remains incomplete for fetch reconciliation. Cached categories missing from the current skeleton are omitted; skeleton children missing from cache are added to their parents while those parents stay incomplete. Cached child folders use the current skeleton category data. Restore units apply directly to the session-owned model in bounded batches. Each batch skips a folder that is already complete or whose known version changed after login, and keeps live records when a cached row has the same ID. A server fetch then replaces the folder's children and removes stale entries. The cache reader validates scope owners, roots, parent links, cycles, child counts, row values, and model limits before it returns data. It caps the estimated decoded tree at 256 MiB, charging 1 KiB per item, 256 bytes per category, and the UTF-8 bytes in stored names and descriptions. A failed validation invalidates the current scopes. `storage` owns SQLite connections and worker mechanics; `inventory` owns SQL, migrations, row mapping, and version checks. `network::Grid` supplies the selected login configuration's stable grid ID.

### `crates/math`

Provides shared geometry and numeric primitives, with selected `glam` types re-exported through this crate. UV transforms are shared by World appearances and decoded materials. Frustum operations use zero-to-one clip depth; ray intersections preserve the parameter in `origin + direction * t`, including for unnormalized directions.

### `crates/network`

Owns login, session lifecycle, simulator links, and capability traffic. A session coordinates the network thread, primary and neighbor links, event routing, handoff, logout, and capability-event decoding. Each circuit owns one simulator's UDP socket, LLUDP ordering and delivery state, send pacing, and bounded packet admission. Capability discovery and event queues share the bounded HTTP client; event envelopes carry retained-memory charges with their events. Capability range GETs preserve the selected redirect policy, cap both partial and full responses, and report 206 responses separately from bounded 200 responses with parsed range metadata when present. Ordinary GETs continue to reject 206. Session events include source-specific ordering evidence, while bounded command and event admission preserve protocol order and report coverage loss separately from ordinary failure. World and rendering state belong elsewhere.

### `crates/protocol`

Owns Second Life wire types, LLUDP framing and field codecs, and typed messages grouped by protocol area, including `ParcelOverlay` and `ParcelProperties`. Each typed message owns its codec and allocation preflight; a declarative list generates message variants and ID dispatch. Build-generated schema metadata comes from a vendored, SHA-256-verified template and remains the fallback for untyped messages. External message spellings and layouts stay exact. Framing and allocation validation belong here, while domain acceptance belongs to World.

### `crates/render`

Derives bounded scene state from World and Assets, then renders it through GPU-owned resources. Reconciliation reads bounded World pages and change journals; it owns visibility and mesh demand, selects prim detail, tessellates prims and sculpt maps, builds terrain and water geometry, and resolves materials. Region and parcel environment assignments come from World and publish as decoded scene environments; experience overrides bypass World and are published through Render.

`scene::prim`, `scene::sculpt`, and `scene::surface` build the reusable CPU `assets::mesh::Mesh`; `scene::mesh` retains meshes and their identities. Sculpt generation takes bounded decoded RGBA maps and uses a cache key containing the asset, sculpt type, flags, detail, image size, and discard level. Texture demand and placeholder lifecycle remain scene integration work. The model layer holds scene objects, regions, patches, and recovery status. `SceneView` applies sequence-checked batches and acknowledges delivery; abandoned deliveries trigger recovery, and stale work cannot publish after recovery or teardown. GPU modules own surfaces, buffers, textures, draw preparation, and resource retirement.

Frame preparation caches per-item transforms, bounds, materials, and mesh faces against scene changes. Each face stores an interned draw group and packed parameter bytes; each item stores packed transform bytes. A CPU draw-list layout runs when visible faces, draw keys, or the scene origin change. It packs opaque faces into contiguous group ranges, sorts blended faces back to front, and derives visible texture and terrain demands from active groups. Pose and animation changes patch packed instance ranges. The viewer's predicted self-avatar pose is applied to its avatar item through the same pose-patch path, and picking reads that updated cached transform. Camera movement rebuilds candidates and lays out again only when visibility changes; otherwise it re-sorts blended faces. Picking walks visible cached faces directly. Shared bounded GPU pages hold geometry from every mesh kind, and indirect batching preserves the no-`INDIRECT_FIRST_INSTANCE` fallback. A stable scene origin avoids rewriting instance transforms for small camera moves. GPU memory limits admit nearer and larger meshes first; instance-budget omissions keep nearer and larger objects and report their reason in the viewport diagnostics.

World stores texture animation as a validated appearance facet observed from full and compressed updates. Empty full blocks clear it; terse and cached updates leave it untouched. Render owns the animation clock, interprets the mode flags, and evaluates the pure UV transform only for matching visible faces before composing it with the face transform. A visible animated face keeps the viewport frame scheduler active. When no dynamic animated face is visible, rendering returns to change-driven redraws.


Terrain settings belong to each World region. Render derives a clamped composition coordinate per vertex from the four handshake start heights and ranges, terrain height, and globally positioned noise. The vertex shader interpolates that scalar, and the fragment shader samples the official per-fragment ramp before mixing the four detail albedos in the viewer's nested order. The 256 ramp samples come from the first row of `alpha_gradient_2d.j2c` at viewer revision `e34b5c188e758b6d24b768cc44fbee459be2855c` and use linear clamp sampling at composition-coordinate y=0. Scene asset demand publishes ready handles with the region; the terrain fragment sends blended albedo through the shared `shade_surface` path, with a neutral fallback while a detail texture is unavailable. Terrain uses filtered texture mipmaps at distance. It does not build the legacy viewer's cached low-resolution terrain composite, so distant texture appearance still needs a live comparison.

Terrain normals use the classic four diagonal height samples at a two-meter stride and sample across loaded patch and region neighbors.

The surface camera uses one infinite reversed-Z projection for objects, terrain, and water, preserving depth ordering without a distance-based far clip. Object range culling and detail selection still use draw distance; terrain and water stay eligible throughout loaded regions and remain limited by the camera view frustum.

### `crates/storage`

Owns versioned, size-bounded persistent bytes. Each consumer opens a root and declares its fixed namespace table as validated relative directories and lowercase alphanumeric extensions. A key is a namespace index and a 128-bit name; storage resolves it to `<namespace>/<first-two-name-hex>/<hyphenated-lowercase-name>.<extension>`. The asset root keeps its payload layout and stores its index in `index.sqlite`. The database records namespace declarations and entry metadata, with the format version in `PRAGMA user_version`. Entry rows use `(namespace, name)` as their primary key. Namespace changes remap retained directory and extension pairs, remove rows for removed namespaces, then let the orphan sweep delete their payloads.

The generic SQLite worker keeps each connection on a dedicated thread. Normal transactions hold at most 256 rows and 1 MiB of estimated payload, which limits lock duration and the work held by one commit. The one-time asset index startup migration is an exception: when namespace declarations change, it can remap up to 262,144 entry rows in one transaction. The queue admits at most 64 normal commands, 131,072 rows, or 32 MiB, with a bounded reserved control queue for recovery work. These caps allow short bursts without retaining a whole inventory update. Reads run on the same worker. The worker enables WAL, applies a 25 ms busy timeout, and runs `quick_check` when it opens a database. A per-database maintenance lock protects repair: the worker removes the database and WAL files only after every process has released its shared lock. Corrupt files and incompatible schemas are recreated. Busy writes return a typed outcome so consumers can defer cache work while keeping completeness conservative.

The asset cache opens the `assets/` consumer root under the default cache directory, so its index is `cache/assets/index.sqlite`. Asset payloads are stored as raw normalized network bytes: textures use `assets/textures/<pp>/<uuid>.j2c`; PBR materials use `assets/materials/pbr/<pp>/<uuid>.llsd`; legacy materials use `assets/materials/legacy/<pp>/<uuid>.llsd`; environments use `assets/environments/<pp>/<uuid>.llsd`. PBR files are LLSD-wrapped glTF JSON; legacy material and environment files are LLSD. The separate material directories distinguish their encodings. Other asset namespaces can be added when those kinds are supported. A future object cache can open a separate consumer root with its own index and size limit.

At open, storage loads the bounded entry table into its in-memory map and LRU-ordered candidate list. Lookups never query SQLite. They reject entries above the caller's byte limit before opening or allocating for their payloads, then verify each file's size and SHA-256. The single cache writer stages a replacement beside its fixed destination and atomically renames it before committing the row through the bounded SQLite worker. A crash before the row commit leaves an orphan payload for the bounded sweep; an old row whose file no longer matches returns Corrupt and is removed. Usage touches are flushed in batches. The writer delegates ranking to an `EvictionPolicy` while retaining selection, index, file, and quota mechanics; generic callers use LRU, and asset storage supplies its reuse-aware policy. Each selection examines at most 128 candidates and each writer batch removes at most 32 entries, off the lookup path. Protected entries are excluded while any live demand lease holds their key. If protected content leaves no room under the limit, writes are rejected and the cache stays over limit until demand releases allow bounded eviction to continue. The writer keeps the process lock and sweeps orphan files and obsolete snapshot, journal, and temporary files in bounded directory steps. Shard directories are created lazily, removed when empty, and included in size accounting. Consumers choose keys and validate their domain payloads; storage owns hashing, quotas, locking, recovery, and eviction mechanics.

The inventory cache uses one `inventory.sqlite` file below the default cache directory. `Grid::id()` returns the stable ID selected by login configuration; the cache stores that value as-is after validation and never uses a login URL, capability, agent name, session ID, simulator address, or grid display name as identity. The scope key is `(grid_id, owner_id)`: personal inventory uses the authenticated agent ID, and the Library uses `inventory-lib-owner`, shared by agents on that grid. No inventory kind is stored. Change sets go through the bounded SQLite worker. The writer invalidates affected folders first, commits category and item changes in bounded transactions, and commits completeness markers last after their children. A queue admission failure or Busy write advances the affected scopes' cache generation, so older complete markers cannot be reused. SQLite reads and restore validation run off-thread; the session applies restore units without blocking the fetcher. On open, the old per-grid/per-agent layout is removed best-effort while respecting maintenance locks.

### `crates/test-support`

Provides shared LLUDP vectors and a hex parser, texture samples with independent pixel expectations, and synchronous allocation measurements. Production crates use it only as a dev-dependency. Network keeps its process-wide probes local because they measure a different scope.

### `crates/utils`

Provides shared domain ID newtypes and small general-purpose helpers such as atomic file replacement. ID wrappers keep UUID representation private, and domain-specific validity rules stay with each owning type. It has no subsystem dependencies.

### `crates/world`

Owns accepted simulator state for regions, objects, relationships, poses, appearances, terrain, media, environment, and parcel observations. Each active region owns its current parcel properties, complete parcel overlay, region flags, and effective restrictions alongside its environment selection. Parcel overlays publish atomically after all parts arrive, and stale property replies cannot replace the newer current parcel. Region retirement releases these observations with the region. Mutations validate and plan before committing state and indexes. Full observations and partial patches share one field pipeline for validation, authority, and freshness; separate update clocks preserve untouched fields. Texture animation is an object appearance facet whose wire mode, target face, frame-sheet dimensions, and timing values are validated on observation. PBR assignments remain distinct from face overrides. Agent handoff is an observation from the destination region that may move the self agent.

Bounded reads and change history expose current state, unresolved relationships, and whether more data is available. Consumers resynchronize when journal history has been evicted.
